# Phase 5.0 — Knowledge Foundation

This phase adds the structured-truth-plus-belief layer the game needs before
any of the Category A minigames can stop being dice rolls. It introduces two
new state objects (Trait Cards and Known Facts), a persona-first generation
pipeline, and a state-conditioned Heart Throb generator. No minigames are
built in this phase — the foundation is the deliverable.

**Read alongside:** `paradise-hearts-glossary.md` (vocabulary), `12-Challenges-And-Events.md` (minigame design intent), `03-LLM-Architecture.md` (agent boundaries).

## 0. North star

By the end of Phase 5.0:

- Every Heartbreaker has a structured Trait Card derived from a coherent persona
  summary, generated by a chained LLM pass at session start (or loaded from a
  curated JSON file in mock-LLM mode)
- The player and each NPC carry a Known Facts dictionary that records what
  they've learned about each other, with source provenance and confidence
- Conversation intents in the wheel are tagged with reveal tiers; selecting
  them at sufficient familiarity unlocks structured facts in addition to the
  existing memories
- Gossip intent is a real mechanic — NPCs share other NPCs' facts at lower
  confidence, sometimes distorted
- Heart Throbs are generated as state-conditioned disruptors via a separate
  pipeline that analyzes villa state and writes a persona designed to threaten
  a specific existing connection
- The cast popout's right rail surfaces what the player has learned about each
  NPC, with citations

No minigame uses this yet. Phase 5.1+ builds Compatibility Quiz and the rest
on top.

## 1. Schema

All new types live in `src/game/state/traits.py`. `IslanderState` and
`PlayerState` in `src/game/state/models.py` gain references to them.

### `PersonaSummary`

The narrative core of an NPC. Generated by LLM, used as context for every
downstream call. **Engine-internal — never exposed to the player UI.**

```python
class PersonaSummary(BaseModel):
    model_config = ConfigDict(extra="forbid")

    one_line: str           # "26. Liverpool primary teacher. Easy-going on the
                            #  surface. Has left every relationship before the
                            #  other person could."
    voice_notes: str        # how they talk, what they avoid, verbal tics
    history: str            # 2-3 paragraph backstory prose
    contradictions: list[str]  # ["warm but guarded", "loyal but afraid to be chosen back"]
    secret_engine: str      # the gravitational force driving every trait
                            # NOT a fact, a motivation — e.g., "she abandons
                            # people first to avoid being abandoned"
```

`secret_engine` is the most important field. The generator is instructed:
*"Every trait must be consistent with the secret_engine."* This is what makes
characters feel coherent instead of like a collection of disconnected facts.

### `TraitFact`

A single piece of structured knowledge about an NPC.

```python
class TraitFact(BaseModel):
    model_config = ConfigDict(extra="forbid")

    key: str                # "biggest_fear"
    value: str              # "being chosen and then unchosen"
    distractors: list[str]  # 3 plausible but wrong alternatives for quizzes
    tier: int               # 1-4 (familiarity threshold to reveal directly)
    reveal_tags: list[str]  # ["deep_chat", "social_event_biggest_fear"]
    mechanical: bool        # True = used in minigame quizzes; False = flavor-only
```

`mechanical=True` facts are the 12 core fields used by Compatibility Quiz,
Couples Quiz, Lie Detector. `mechanical=False` facts are flavor (karaoke
song, weirdest dating story) — they show up in cast popouts and LLM
conversation context but never appear as quiz questions.

### `TraitCard`

The full structured truth about an NPC.

```python
class TraitCard(BaseModel):
    model_config = ConfigDict(extra="forbid")

    persona: PersonaSummary

    # Core traits (12 mechanical fields, tiered)
    core_traits: dict[str, TraitFact]

    # Flavor traits (open-ended, 6-10 per NPC)
    flavor_traits: dict[str, TraitFact]
```

The 12 core trait keys are fixed:

| Tier | Keys |
|---|---|
| 1 (familiarity 0+) | `occupation`, `hometown`, `age` |
| 2 (familiarity 25+) | `favorite_food`, `hobby`, `drink_of_choice` |
| 3 (familiarity 50+) | `biggest_fear`, `love_language`, `worst_habit`, `pet_peeve` |
| 4 (familiarity 75+) | `insecurity`, `past_heartbreak`, `hidden_secret` |

Flavor trait keys are NOT fixed — they're whatever the generator (or content
author) wants. Suggested catalog: `karaoke_song`, `comfort_show`,
`signature_dance_move`, `weirdest_dating_story`, `unexpected_skill`,
`irrational_food_opinion`, `thing_they_lied_about_in_their_bio`,
`item_they_brought_to_paradise`.

### `KnownFact`

A single piece of knowledge in someone's head. Truth or belief — they're
indistinguishable to the holder; only the engine knows.

```python
class KnownFact(BaseModel):
    model_config = ConfigDict(extra="forbid")

    fact_key: str           # "chloe.biggest_fear"
    value: str              # what the knower believes (may be wrong if rumor)
    source: Literal["direct", "social_event", "gossip", "witnessed"]
    source_npc_id: str | None      # who told them, if gossip
    learned_on_day: int
    learned_on_turn: int
    confidence: float       # 0.0-1.0
    citation: str           # human prose for popout: "Chloe told you at the
                            # firepit on Day 3 evening"
```

### `KnownFacts`

A dict on each Heartbreaker and the Player.

```python
KnownFacts = dict[str, KnownFact]   # key = "{npc_id}.{trait_key}"
```

Added to state models:

```python
class IslanderState:
    # ...existing fields...
    trait_card: TraitCard
    known_facts: KnownFacts = Field(default_factory=dict)

class PlayerState:
    # ...existing fields...
    known_facts: KnownFacts = Field(default_factory=dict)
```

Schema bump: `SCHEMA_VERSION` → 25. All fixtures regenerate.

### Validation

The generator MUST pick one `secret_engine` from the chosen template's list
(or a coherent variation). The engine REFUSES to generate two NPCs with the
same secret_engine in one run (forces cast variety). Big5 values must land
within the template's bias range.

## 3. Persona-first generation pipeline

One chained LLM call per NPC, batched 8 at once (single prompt, returns 8
trait cards). Total: 1 LLM call per session at start.

**Agent:** `src/game/agents/trait_generator.py` — new agent, uses gpt-5.4-mini
for structured output.

### Step 1 — Engine prepares 8 seeds

For each cast slot, pick an archetype + gender + age_band. Existing logic in
`src/game/engine/character_creation.py` already does this for the opening
8 — extend to also pick a target template and bias values.

```python
@dataclass
class GenerationSeed:
    slot_id: str            # "chloe", "maya", ...
    archetype_id: str       # "sweetheart"
    template: ArchetypeTemplate
    gender: Gender
    age_band: tuple[int, int]   # (24, 30)
    used_secret_engines: list[str]  # already-claimed engines this run (for variety)
```

### Step 2 — LLM call (chained internally)

System prompt instructs the model to produce, for each seed, a complete
TraitCard. The prompt is structured to enforce the chain:

```
For each Heartbreaker:

  1. Write the persona summary first.
     Pick one secret_engine from the template's typical list (or a coherent
     variation that fits the same emotional shape). Write one_line, voice_notes,
     history (2-3 paragraphs), and 2-3 contradictions. Do NOT write traits yet.

  2. Now write the 12 core traits.
     Each value must be consistent with the persona's secret_engine. If she's
     a self-abandoner, her worst_habit is ghosting, not loud-chewing. Her
     biggest_fear is being chosen and still left, not spiders.

  3. Now write 6-10 flavor traits.
     These exist for color. Surprising specifics are good. A Sweetheart who
     collects fridge magnets from places she's never been. An Alpha who runs
     on caffeine and dread. Avoid generic.

  4. Distractors come in a follow-up call (cheaper).
```

Output schema (per NPC):

```json
{
  "persona": { "one_line": "...", "voice_notes": "...", "history": "...",
               "contradictions": [...], "secret_engine": "..." },
  "core_traits": {
    "occupation": { "value": "...", "tier": 1 },
    "biggest_fear": { "value": "...", "tier": 3 },
    ...
  },
  "flavor_traits": {
    "karaoke_song": { "value": "Stay by Rihanna" },
    ...
  }
}
```

Engine validates:
- All 12 core trait keys present
- secret_engine not duplicated across the cast
- Big5 bias respected (if Big5 was generated alongside)
- No tier-mismatched values (e.g., a tier-4 secret stuffed into tier-1)

If validation fails, regenerate that single NPC (cheap targeted retry).

### Step 3 — Distractor generation

Separate LLM call (gpt-4.1-mini, cheaper). For each non-flavor TraitFact,
generate 3 plausible-but-wrong alternatives. This is bulk work; one call
covers all 8 NPCs × 12 traits = 96 facts.

```
For each trait, write 3 distractors that are:
- Plausible (someone might believe this)
- Coherent with the NPC's archetype (not wildly off-character)
- Different from each other
- Different from the true value
```

### Step 4 — Cache and store

The complete TraitCard is written into `state.islanders[i].trait_card`.
Determinism: same seed → same RNG → same archetype assignments → same
generation prompts → same outputs (with the LLM's temperature 0 in
generation mode).

### Mock-LLM mode

When `PARADISE_MOCK_LLM=1`, the generator does NOT call the LLM. Instead it
loads from `src/game/content/curated_cast.json` — a hand-curated set of 8
Heartbreakers + 4 Heart Throbs. See §5.

This keeps tests deterministic and fast, plus gives us a known-good cast for
demos.

## 4. Heart Throb generation

Heart Throbs are state-conditioned weapons, not random arrivals. The Producer
AI runs a brief generator that analyzes the current state and writes a target
brief, then the same trait generator runs with that brief layered on top.

### Disruption modes

```python
class ThreatMode(StrEnum):
    TEMPT_PLAYER = "tempt_player"            # match player's Type on Paper
    STEAL_PARTNER = "steal_partner"          # match partner's Type
    BREAK_RIVAL = "break_rival"              # threaten a non-player couple
    SHAKE_ALLIANCE = "shake_alliance"        # high chemistry with target's friends
    EXPOSE_HISTORY = "expose_history"        # share past with target
    INJECT_CHAOS = "inject_chaos"            # high-graft, low-loyalty disruptor


class HeartThrobBrief(BaseModel):
    model_config = ConfigDict(extra="forbid")

    target_npc_id: str            # who they're built to threaten
    threat_mode: ThreatMode
    archetype: str                # still has one for flavor
    persona_hook: str             # specific element to weave in
                                  # e.g., "shares hometown with target",
                                  # "ex of someone the target knows",
                                  # "embodies the partner's ideal"
```

### Trigger logic

Producer AI runs this each ceremony night and at the Flush of Hearts arrival.

```python
def pick_heart_throb_brief(state) -> HeartThrobBrief:
    player_couple = state.player_couple
    couple_strengths = [(c, state.couple_strength(c)) for c in state.couples]

    # Stable player couple → tempt the player
    if player_couple and player_couple.strength > 70:
        if random.random() < 0.5:
            return HeartThrobBrief(
                target_npc_id="player",
                threat_mode=ThreatMode.TEMPT_PLAYER,
                archetype=pick_archetype_matching(state.player.type_on_paper),
                persona_hook="embodies the type the player picked at character creation",
            )
        else:
            return HeartThrobBrief(
                target_npc_id=player_couple.partner.id,
                threat_mode=ThreatMode.STEAL_PARTNER,
                archetype=pick_archetype_matching(player_couple.partner.type_on_paper),
                persona_hook="threatens to be what the partner was waiting for",
            )

    # Player is single → help them by offering a high-chemistry match
    if not player_couple:
        return HeartThrobBrief(
            target_npc_id="player",
            threat_mode=ThreatMode.TEMPT_PLAYER,
            archetype=pick_archetype_matching(state.player.type_on_paper),
            persona_hook="appears as a clean second-chance match",
        )

    # Cast too aligned, no drama → inject chaos
    if state.drama_index() < 30:
        return HeartThrobBrief(
            target_npc_id=random.choice(state.npcs).id,
            threat_mode=ThreatMode.INJECT_CHAOS,
            archetype="joker",
            persona_hook="enters loud, flirts indiscriminately",
        )

    # Default: break the most stable NPC couple
    strongest_npc_couple = max(couple_strengths_excluding_player(state),
                                key=lambda x: x[1])
    return HeartThrobBrief(
        target_npc_id=strongest_npc_couple[0].partner_a_id,
        threat_mode=ThreatMode.BREAK_RIVAL,
        archetype=pick_archetype_matching(
            state.find_npc(strongest_npc_couple[0].partner_b_id).type_on_paper
        ),
        persona_hook="targets the strongest couple",
    )
```

### Generation with brief

Same persona-first pipeline as the opening cast, but the prompt receives the
brief and additional context:

```
You are writing a Heart Throb — a new arrival designed to shake an existing
relationship.

Target: Chloe (the player's partner). Her secret_engine is "abandons people
first to avoid being abandoned." She's coupled to the player at strength 72.

Brief: STEAL_PARTNER. Write someone who would tempt Chloe specifically — not
just attractive, but someone whose presence makes her question her own choice.

Persona hook: "embodies the type Chloe was waiting for." Their secret_engine
should resonate with Chloe's wound — either by mirroring it or by being its
opposite.

Now write the persona summary, core traits, and flavor traits as you would
for any Heartbreaker, but with this resonance baked in.
```

### Count and timing

Two Heart Throb arrivals per 6-day run:

- **Day 3 morning** — first arrival, mid-game tension
- **Day 4-5** — Flush of Hearts arrival (3 at once, batched), all generated
  via the same pipeline with separate briefs

(The Flush of Hearts ones can run with diverse modes — one TEMPT_PLAYER, one
BREAK_RIVAL, one INJECT_CHAOS — to maximize drama.)

### Player visibility

The brief, the `target_npc_id`, the `threat_mode` — none of these are EVER
visible to the player or in the UI. The producer's reasoning stays
engine-internal. The player should feel the resonance ("...wait, why does
this person remind me of...") without being told it was engineered.

## 6. Fact reveal mechanics

### Intent → reveal tag table

Conversation intents in the wheel already carry a `category`. We add a
`reveal_tier` (0 = no fact reveal; 1-4 = unlocks tier-N fact) and a
`reveal_tag` (which fact, if any).

```python
class ContextualOption(BaseModel):
    # ...existing fields...
    reveal_tier: int = 0              # 0 = no reveal
    reveal_tag: str | None = None     # which trait key, if specific
```

Suggested mapping (codex tunes during implementation):

| Intent kind | Reveal tier | Notes |
|---|---|---|
| `friendly_chat_villa` | 1 | random tier-1 fact |
| `friendly_compliment_personality` | 2 | random tier-2 fact if familiarity ≥ 25 |
| `friendly_ask_about_them` | 1-2 | tier scales with familiarity |
| `deep_ask_life` | 3 | random tier-3 fact if familiarity ≥ 50 |
| `deep_share_feelings` | 3-4 | tier-3 always; tier-4 only at familiarity ≥ 70 + success |
| `deep_vulnerable_share` | 4 | tier-4 hidden secret, only at familiarity ≥ 75 + success |
| `ask_gossip:about_<npc>` | 2-3 (about the gossip target, not the gossiper) | distortion possible |
| `banter_*` | 0 | flavor only, no fact reveal |
| `flirty_*` | 0-1 | rare tier-1 reveal |
| `supportive_*` | 0 | reinforces but doesn't reveal |
| `exit_*` | 0 | |

### Curator extension

`src/game/engine/turn_curator.py` already runs at conversation end. Extend it
to emit `KnownFact` entries when:

1. The conversation contained intent(s) with `reveal_tier > 0`
2. The mechanical roll succeeded (failure = NPC deflects, no reveal)
3. The required familiarity threshold is met
4. The fact hasn't already been learned by the player

```python
def emit_fact_reveal(
    state: GameState,
    intent: ContextualOption,
    target_npc: Islander,
    holder_id: str = "player",
) -> KnownFact | None:
    if intent.reveal_tier == 0:
        return None
    if state.familiarity_with(target_npc) < TIER_THRESHOLDS[intent.reveal_tier]:
        return None
    fact_key, fact = pick_revealable_trait(target_npc.trait_card, intent.reveal_tier,
                                           already_known=state.player.known_facts)
    if fact is None:
        return None
    known = KnownFact(
        fact_key=f"{target_npc.id}.{fact_key}",
        value=fact.value,
        source="direct",
        source_npc_id=None,
        learned_on_day=state.day,
        learned_on_turn=state.turn_index,
        confidence=1.0,
        citation=f"{target_npc.name} told you on Day {state.day} at the "
                 f"{state.location_id.value}",
    )
    state.player.known_facts[known.fact_key] = known
    return known
```

### Social event broadcasts

When a social event runs (Phase 5.5+), every Heartbreaker who attends learns
the fact simultaneously at `source="social_event"`. The fact `confidence` is
1.0 because everyone heard them say it.

For Phase 5.0, the broadcast hook exists in code (`broadcast_fact_to_attendees`)
but isn't wired to actual social events yet — those build in 5.5.

## 7. Gossip mechanics

### New intent: `ask_gossip:about_<npc_id>`

When the player chats with NPC A at familiarity ≥ 30 AND NPC A has known
facts about NPC B (at any source), the wheel can surface
`ask_gossip:about_<B>` as an option.

The gossip exchange:

```python
def share_gossip(
    state: GameState,
    speaker: Islander,
    listener_id: str,
    subject_npc: Islander,
) -> KnownFact | None:
    # Speaker shares one of their known facts about subject_npc
    speaker_facts_about_subject = [
        kf for kf in speaker.known_facts.values()
        if kf.fact_key.startswith(f"{subject_npc.id}.")
        and not kf.fact_key.endswith((".hidden_secret",))  # never gossips secrets
    ]
    if not speaker_facts_about_subject:
        return None
    fact_to_share = pick_juiciest(speaker_facts_about_subject)

    # Distortion: chance the gossiper twists the value
    distortion = compute_distortion(speaker)  # personality-driven
    actual_truth = subject_npc.trait_card.get_fact(fact_to_share.fact_key.split(".")[1])
    if random.random() < distortion:
        value = random.choice(actual_truth.distractors)
    else:
        value = fact_to_share.value

    known = KnownFact(
        fact_key=fact_to_share.fact_key,
        value=value,
        source="gossip",
        source_npc_id=speaker.id,
        confidence=0.6,
        citation=f"{speaker.name} told you on Day {state.day} that {subject_npc.name}...",
    )
    state.find_islander(listener_id).known_facts[known.fact_key] = known
    return known
```

### Distortion factors

Higher distortion (more likely to twist) when:
- Speaker has `dramatic` personality tag (chaotic, joker archetype)
- Speaker dislikes subject (low affection + friendship)
- Speaker is jealous (high chemistry between subject and someone speaker likes)

Lower distortion when:
- Speaker is friend archetype with high integrity
- Speaker has direct relationship with subject (source="direct" on the fact they're sharing)

Range: 0.0 to 0.5 (cap at 50% chance to lie even for the most dramatic).

### Why this matters

Phase 5.1's Compatibility Quiz will draw from player's known_facts. If the
player relied on gossip and got distorted values, they'll fail quiz questions
in ways that feel earned. This is a real strategic layer: **direct chat is
slow but reliable; gossip is fast but risky.**

## Appendix B — Sample generation prompts

### Opening cast (8-NPC batched prompt)

```
You are generating 8 Heartbreakers (contestants) for a reality dating show
called Paradise Hearts. Each must be a fully realized character with internal
coherence.

For each Heartbreaker, you will produce:
1. A persona summary (one_line, voice_notes, history, contradictions, secret_engine)
2. 12 core traits (occupation, hometown, age, favorite_food, hobby, drink_of_choice,
   biggest_fear, love_language, worst_habit, pet_peeve, insecurity, past_heartbreak,
   hidden_secret)
3. 6-10 flavor traits (open-ended; surprising specifics)

RULES:
- The secret_engine is the gravitational force driving every other trait.
  Write it FIRST in the persona, then derive every fact from it.
- Each NPC must have a DIFFERENT secret_engine. No duplicates across the cast.
- The "easy" answer is forbidden. Surprising specifics are better than archetypal ones.
- "She's afraid of spiders" — boring. "She's afraid of being chosen and then
  unchosen" — character.
- Reference the archetype template provided for each slot. Use the typical
  secret_engines as inspiration, but feel free to write coherent variations.
- All ages within the provided age_band.
- Big5 values within the bias range.

Slot 1: archetype=sweetheart, gender=woman, age_band=(24, 30)
Slot 2: archetype=alpha, gender=man, age_band=(26, 32)
...
Slot 8: archetype=friend, gender=man, age_band=(24, 30)

Return a single JSON object with key "cast" mapping slot_id to TraitCard.
```
